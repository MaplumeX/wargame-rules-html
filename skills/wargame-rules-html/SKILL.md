# 规则书整理成 HTML

把一本规则书变成玩家在桌边真正用得上的网页。转录要忠实，结构要围绕“对局时怎么查”来设计。

下文的路径都相对于本 skill 的目录。先确认依赖可用，缺什么告诉用户：`python3 -c "import markdown, PIL"`、`pdfinfo -v`。

## 流程

### 1. 体检并给出方案

```bash
python3 scripts/prepare_pdf.py inspect <pdf>
```

再抽看封面、目录和几页内容页，弄清语言、版式、规则编号形式、图表类型、回合结构（固定回合、时段、交替激活）。向用户说明情况和方案，并确认两件事：

- **改写尺度**：原文不改，还是允许改写。
- **规则书之外的材料**：辅助卡、勘误、FAQ 是否一并收录。这些经常不在规则书里，却是对局最常查的内容。

确认后再动手，因为转录是最耗时的一步，方向错了代价很大。

### 2. 建工作目录并渲染

工作目录放在用户的项目旁边，不要放进本 skill 目录：

```bash
python3 scripts/prepare_pdf.py render <pdf> <book-dir>
```

可以复制 `assets/example-book/` 作为起点，它是一本虚构的小规则书，展示了全部语法。

### 3. 转录并写章节稿

把内容写进 `<book-dir>/src/*.md`，格式见 `references/source-format.md`。

- **逐页看 `pages/` 下的图片转录**，不要依赖 OCR。浅色小字、算式和表格里的数字，OCR 很容易认错，而一个数字错了规则就错了。如果当前环境看不了图片，就用 OCR，并明确告诉用户这份结果需要更严格的人工校对。
- **文字版 PDF** 可以先用 `pdftotext -layout` 取文字，但仍要对照原页检查双栏顺序和表格。
- **每处理几页就保存一次**。长文档会超出单次对话能记住的范围，已落盘的内容不会丢。
- **褪色或靠近装订线的文字**用 `prepare_pdf.py zoom` 放大核对，尤其是数字。
- 边转录边记下规则书自身的问题：重复编号、错误引用、前后矛盾。

规则书里的插图记入 `crops.txt`，然后运行 `crop` 和 `contact`，查看拼图确认裁得对。历史照片这类装饰可以不收录。

### 4. 改写原则（用户允许改写时）

玩家会按这份页面裁决争议，所以准确比流畅重要。

- **保留**每个数字、条件、例外、取整方向、时机和主语（谁做、谁选择）。
- **不补全原文没写的内容**。原文疑似漏字时照原样处理，或写入整理说明，不要替作者决定。比如原文只说了前两点损失的后果，表格就不要多出一列“第 3 点损失：—”，那会暗示没有效果。
- **不缩小或扩大范围**。“不影响其防御支援能力”和“不影响它已提供的防御支援”含义不同。
- **用结构代替长句**：并列规则变表格，多重条件变清单，流程变编号步骤，二选一变左右对照。
- **规则书的错误不要悄悄修**，列入“整理说明”，写明原文情况和处理方式。
- **自己新增的内容要标明**。没有规则号的章节会自动带“整理补充”标记，内容里要注明依据的规则号。

### 5. 设计对局结构

先和用户确认结构，再写配置，格式见 `references/book-config.md`。

顶层按使用时机组织，而不是按规则书章节顺序：一个规则在玩家第一次需要它的阶段出现。典型结构是开局、回合流程、各行动阶段、回合结束、参考资料，但要跟着游戏走：交替激活、卡牌驱动、无固定回合的游戏，阶段的划分都不一样。

- **规则号保持原书编号**，只改编排，这样玩家可以和纸质规则对照。
- **每个阶段开头放操作清单**（写在 `parts.md`），每步链接到规则。
- **汇总常查的数值**，例如战斗修正、地形、撤退距离，放在用到它们的阶段最前面。
- **游戏有固定回合表时**，配置 `turns` 生成回合轨和日历，把增援、事件、规则变化按回合列出。回合流程可以按时段筛选步骤，写法见 `references/source-format.md`。游戏没有回合表时不要硬凑，省略 `turns` 即可。

### 6. 构建和检查

```bash
python3 scripts/build.py <book-dir>
node scripts/check.mjs <book-dir>/out.html
```

`build.py` 校验引用、编排和残留标记，出错时返回非 0。`check.mjs` 跑交互和版式检查，并在 `shots/` 生成桌面和手机截图，要实际查看这些截图。没有浏览器或 Node 时跳过这步，并告诉用户没有测过。

页面样式问题可查 `references/troubleshooting.md`。

### 7. 校对和交付

自动校验只能证明结构正确，不能证明规则转录正确。交付前对照原图逐项核对表格和数值，再抽查改写最多的章节。

交付时告诉用户：

- 是否有没核对或无法确认的内容，这一点放在最前面；
- 发现的规则书问题及处理方式；
- 没有收录的内容，例如辅助卡上的表格。

## 版权

规则书通常受版权保护。页面默认只作为本地文件交给用户，不要主动发布，也不要把规则正文或扫描图提交到公开仓库，除非用户确认自己有权这样做。
